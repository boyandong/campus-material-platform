# 暑假目录帖 14 天验证手册

## 成功标准

第一轮同时满足以下条件，才算暑假需求获得初步验证：

- 目录累计浏览量不少于 500
- 有效咨询者不少于 10 人
- 已交付且未退款的交易不少于 5 笔
- 不同买家不少于 3 人
- 至少 2 个品类产生交易
- 自然浏览、免费详情帖或朋友推荐产生的订单占比不低于 30%
- 实际推广费不超过 26.4 元

达到 10 单是强信号；100 单仍是开发正式网站前的长期里程碑。

## 第 1–3 天：审核与准备

- [ ] 向两位提供者逐份确认作者、AI 使用情况、学年、老师和销售授权
- [ ] 删除姓名、学号、联系方式及不必要的原始数据
- [ ] 实验资料只保留适合学习参考的原理、仿真和数据处理内容
- [ ] 将通过审核的资料改为 `review_status=已通过`
- [ ] 确认交付文件后改为 `listing_status=已上架`
- [ ] 检查 `marketing/catalog/` 六张目录图片
- [ ] 检查 `marketing/previews/` 九张私聊样图
- [ ] 将帖子文案中的未通过资料删除，而不是带病上架

## 第 4 天：自然发布与首次置顶

- [ ] 发布总目录帖，填写 L001 的 `published_at`
- [ ] 发布三篇免费详情帖，填写 L003–L005 的 `published_at`
- [ ] 自然观察一段时间，记录自然新增浏览和咨询
- [ ] 晚间执行一次 1 小时置顶，填写 L002 的 `published_at`
- [ ] L001 与 L002 分别记录自然阶段和置顶阶段的新增数据，不填写累计值
- [ ] 置顶期间保持 5 分钟内首次回复

## 第 5–9 天：记录而不是猜测

- [ ] 每位咨询者使用稳定的匿名 `buyer_id`
- [ ] 每次咨询写入 `feedback.csv`，未成交也记录原因
- [ ] 每笔付款写入 `orders.csv`
- [ ] 交付成功后把 `delivery_status` 改为“已交付”
- [ ] 退款不删除订单，只把 `refunded` 改为“是”
- [ ] 每天运行 `python scripts/analyze.py`
- [ ] 不因为一两条意见临时增加大量新品类

## 第 10–11 天：第二轮

- [ ] 使用 B 版目录顺序：实验参考 → 计算机 → 公共课
- [ ] 执行第二次 1 小时置顶，填写 L006 的 `published_at`
- [ ] 只记录这一轮新增浏览、咨询、订单和收入
- [ ] 比较两轮询问编号，检查是否存在首屏位置偏差

## 第 12–14 天：复盘

- [ ] 运行统计脚本并保存输出
- [ ] 检查每个品类的咨询数、交易数和咨询成交率
- [ ] 检查平台佣金是否覆盖推广费
- [ ] 向两位提供者询问是否愿意继续供货
- [ ] 汇总用户主动询问但目录中没有的资料

阶段决策：

- 0–2 单：检查封面、时机和品类，不继续扩充库存
- 3–4 单：只修改一个变量后复测
- 5–9 单：扩充表现最好的两个品类
- 10 单以上：进入 30 单复验，并在开学季重复测试

## 数据填写规则

- `published_at` 为空的发布记录只是计划，不计入实际成本。
- 来源只使用：`目录自然流量`、`校园集市目录置顶`、`免费详情帖`、`朋友推荐`、`团队私聊`。
- 套餐的多行资料必须共用 `transaction_id`，否则会被重复计算为多笔交易。
- 一个买家始终使用同一个匿名 `buyer_id`，否则无法计算复购。
- 平台佣金按对应卖家的 `commission_rate` 计算；当前两位均为 `0.20`。
